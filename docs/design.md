# FactorStore 设计文档

一个因子在一个合约的一个交易日只有一个 `double` 值。再次写入同一位置时覆盖旧值。每个 FactorStore 实例在内存中保存自己的数据。

## 五个接口

| 题目要求 | 接口 | 做法 |
| --- | --- | --- |
| 批量插入某个合约某一年的某个因子 | `upsert_year` | 找到这个年度块，一次写入多天 |
| 批量插入某天一批合约的一批因子 | `upsert_day` | 按因子和合约取值，分别写入当天 |
| 查询当前总共有多少个因子 | `factor_count` | 直接取因子目录的长度 |
| 删除某个因子 | `erase_factor` | 从目录移除因子，并释放它的所有数据 |
| 根据合约列表、日期列表和因子列表查询数据 | `query` | 找到相关年度块，按原始输入顺序返回结果 |

## 数据怎么存

先按因子找目录，再按合约和年份找块。例如，`momentum` 在 `IF2606` 上的 2026 年数据放在同一个块里。库把名称转成整数 ID，块内把日期转成年内日序号。

| 块内记录数 | 存放方式 |
| --- | --- |
| 1 条 | 日期和值直接放在块里，省去两个数组的分配 |
| 少量日期 | 日期和值分别放在数组里，按日期顺序排列，只保存写过的日期 |
| 至少 192 个日期 | 可以换成稠密块。每个自然日都有一个槽，用有效位标记该槽是否写过 |

年度写入可以当场转成稠密块。单日写入可能同时涉及很多块，这时先写值，再分批转换，每批最多转换 256 个块。等待转换的块可以照常读写。

## 查询怎么读

按年整理请求日期，同一个年度块只需找一次。请求范围很宽、某个因子实际存的块很少时，也可以扫描已有块，再对照请求。块内连续存放的一段值可以一次复制。稀疏块中的周五和下周一也可能紧挨着，可以一起读取。

结果按 `[因子][合约][日期]` 排列，保留输入的顺序和重复项。缺失位置用有效位标记，写入的 `0.0` 和 `NaN` 都算有效值。结果会为每个请求组合留位置，例如 16 个因子、2,048 个合约、32 个日期约占 8.13 MiB。

## 并发和扩展

已有的不同因子可以并行读写。批量写入和查询都会先锁齐涉及的因子，所以查询能看到一批成功写入的完整结果。新增名称和删除因子需要独占目录。

内部存储由 `FactorStore::Impl` 管理。需要重启后恢复数据时，可以先增加带版本和校验的快照。数据超过内存容量时，再考虑把年度块放到磁盘上。
