# FactorStore 设计文档

## 目标与交付范围

FactorStore 是一个 C++17 进程内因子库。每个实例持有独立数据。数据单元由因子名称、合约名称和交易日期唯一定位，内容为一个 `double`。交易日期由调用方提供，库使用公历规则校验日期。

| 用途 | 公开操作 | 设计要点 |
| --- | --- | --- |
| 回填某因子在某合约一年内的数据 | `upsert_year` | 一批只访问一个年度块，覆盖输入日期，保留其他日期 |
| 写入每日横截面 | `upsert_day` | 一批处理因子和合约的矩阵，复用已解析的合约索引 |
| 查看当前因子数量 | `factor_count` | 直接读取活动因子目录的大小 |
| 删除一个因子的全部数据 | `erase_factor` | 释放目标因子的块，其他因子的块无需扫描 |
| 读取指定三维列表的数据 | `query` | 按年复用块查找，按输入顺序返回值与有效位 |

## 数据布局

因子是一级目录。每个因子持有一个块索引，键由 32 位合约 ID 和年份组成，即 `(uint64_t(contract_id) << 32) | uint32_t(year)`。合约名和因子名在进入存储路径时解析为整数。新增合约或年份时可单独建立所需的块，已有年度块的数据保持原位。

```text
FactorStore
└── 因子目录
    └── 一个因子
        └── 块索引 [合约 ID + 年份]
            └── 一个 YearBlock
                └── 年内自然日序号 → double
```

块内使用从 0 开始的年内自然日序号，闰年最多 366 个槽。例如 2024 年 2 月 29 日的序号是 59。未写入的日期保持缺失，同一日期重复写入只更新该日的值。

| 块表示 | 结构 | 适用负载 |
| --- | --- | --- |
| 稀疏 | 有序日序号数组和对应的数值数组 | 只为已写入日期分配条目，适合新合约和低密度数据 |
| 稠密 | 366 个 `double` 槽和 366 位有效位图 | 按日序号直接读写，适合高密度历史数据 |

新数据按日期密度选择块表示。已有稀疏块在不同有效日期数达到 **192** 时转为稠密块，转换完成后释放稀疏数组。覆盖已有日期不增加密度。转换后同一块继续以稠密形式工作，删除所属因子时与其他块一起释放。

阶段三对照了纯稀疏、纯稠密和阈值为 192 的混合布局，首版采用该混合布局。在大型高密度无序查询中，混合布局的 P50 从约 8.79 ms 降至 4.33 ms，进程峰值 RSS 增加约 4.7 MiB。大量块在同一批中达到阈值时会集中支付转换成本。测量口径和低密度结果见[性能基准报告](benchmarks.md)。

## 查询输出与成本

查询返回按 `[因子][合约][日期]` 排列的连续值数组，日期轴连续。每个轴保留调用方指定的顺序和重复项。有效位用于区分缺失、已写入的零和已写入的 `NaN`。同一结果中的未知因子、未知合约和未写入日期都以缺失表示。

设三个轴长度分别为 F、C、D，结果有 N = F × C × D 个槽。在常见的 8 字节 `double` 平台，两个结果缓冲区合计约为 `8 × N + 8 × ceil(N / 64)` 字节，另有容器和索引开销。即使存在大量缺失，结果仍保留完整形状。大查询可按因子或日期拆批。

在哈希映射平均查找成本下，因子计数为 O(1)，删除的工作量随该因子的块数增长。年度批量写入先排序后处理单块，稀疏路径线性归并新旧条目，稠密路径按日序号更新。单日批量写入逐项处理 F × C 个值。稀疏块内查询使用二分查找，乱序插入可能移动已有条目。查询分配与初始化的成本至少随 N 线性增长，定位块时按年份分组，以便同一个块服务多个日期。

## 一致性与扩展边界

参数校验在写入前完成。内存不足时，批量写入允许保留已经成功的更新。新因子写入数据后才登记到活动目录，块转换在新缓冲区构建完毕后才替换旧表示。

首版的状态存放在进程内，并发调用由调用方同步。公开接口经由 `FactorStore::Impl` 隔离内部布局。后续可在实现层调整索引、分块阈值或存储后端，保持数据键和调用约定。接口细节见[接口文档](api.md)，源码入口见[代码说明](implementation.md)。
