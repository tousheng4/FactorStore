# FactorStore 实现路线

当前仓库已搭好 C++17 和 CMake 工程骨架。第一版的交付目标是一个通过测试、具备可复现性能基准的内存因子库，完整支持题目要求的五项操作。沿用[项目介绍](introduction.md)中的因子优先布局，每个 `YearBlock` 对应一个因子、一个合约和一个年份。

## 阶段一 · 确定接口契约

先编写公开头文件和 `api.md`。以下命名和行为作为第一版约定，便于实现与测试采用同一套规则。

| 操作 | 建议接口 | 第一版约定 |
| --- | --- | --- |
| 写入某合约某因子的一年数据 | `upsert_year` | 显式传入年份和 `(日期, 值)` 列表。只覆盖本批指定日期，保留该年其他日期的数据。 |
| 写入某天的一批合约和因子 | `upsert_day` | 传入日期、因子列表、合约列表及按 `[因子][合约]` 排列的连续值数组。每个位置写入一个值，已有值被覆盖。 |
| 查询因子数量 | `factor_count` | 返回当前有效的不同因子数。首次成功写入数据时创建因子，覆盖已有数据时数量不变。 |
| 删除因子 | `erase_factor` | 删除指定因子的所有数据，返回是否存在并已删除。删除后可用同名重新写入。 |
| 按三维列表查询 | `query` | 返回按 `[因子][合约][日期]` 排列的连续值数组和有效位图。各维保留输入顺序与重复项，未知名称与未写入的位置均标为缺失。 |

- 日期使用 `YYYYMMDD` 整数。库校验公历日期和年度写入的年份归属，交易日由调用方提供。块内使用从零开始的年内自然日序号，支持闰年。
- 写入时拒绝重复日期、重复写入轴成员及矩阵长度不匹配等非法输入，参数校验在修改数据前完成。空写入不创建因子。第一版不承诺内存分配等运行时失败时整批回滚，失败后目录与计数仍须保持一致。
- 查询允许合法的 `0.0` 和 `NaN`，由位图判断值是否存在。任一查询轴为空时返回空结果。乘积和缓冲区大小在分配前检查，避免整数溢出。

**验收** · `api.md` 给出两种写入和一次查询的完整示例。测试用例能从文档确定覆盖、缺失、输入顺序和错误行为。

## 阶段二 · 实现内存存储和五项操作

1. 建立因子和合约的名称到整数 ID 的映射。因子目录保存各自的块索引，在因子内部用 `ContractID` 和 `Year` 的 64 位组合键定位 `YearBlock`。让这些结构留在库内部，公开 API 继续接收名称与日期。
2. 第一版采用有序日期数组和数值数组的稀疏块。年度写入先校验并整理输入，再定位一次块并合并更新。单日写入每批预解析名称，按因子遍历矩阵并更新各合约的块。
3. 查询预解析名称并对日期按年分组。每个因子、合约和年份组合复用一次块查找，按原始位置填充结果。因子计数从活动目录取得，删除只移除目标因子及其所属块。

**验收** · CTest 覆盖五项接口及其组合，尤其是两种写入互相覆盖、跨年和闰年查询、查询乱序和重复项、合法 `NaN` 与缺失的区分、非法批次前后数据一致，以及删除后同名重建。用简单的三元组映射作为测试参照，对随机写入、删除和查询序列做结果比对。

## 阶段三 · 建立基准并按结果优化

使用已有 `benchmarks/` 目标，在 Release 构建下用固定种子生成可复现的数据。记录数据规模、密度、硬件及构建配置，报告批次延迟、每秒处理的值数量和内存占用。

| 场景 | 对照条件 |
| --- | --- |
| 年度批量写入 | 首次导入、覆盖已有数据、部分日期乱序回补 |
| 单日批量写入 | 首次建块与已有块日更分别测量，改变合约数和因子数 |
| 多维查询 | 单因子跨年、多因子单日、任意日期列表，覆盖不同缺失率 |

根据结果决定下一步。如果单日写入主要耗在块创建，先检查索引和分配开销。如果高密度块的容量或访问成本成为瓶颈，再实现 `double` 数组加位图的稠密块，比较纯稀疏、纯稠密和阈值转换。保留有数据支持的优化，并记录适用的负载和代价。

**验收** · 提供可复现的基准命令和结果。布局或算法改动使用相同数据与基线对比，并重新运行阶段二的正确性测试。

## 阶段四 · 完成首版交付

- `design.md` 说明数据模型、块布局、代价以及扩展点。
- `api.md` 补齐最终签名、输入输出、错误行为和示例。
- `implementation.md` 说明代码入口、批量处理路径、构建测试方式及基准结果。

**验收** · 从干净的构建目录完成 CMake 配置、编译及 CTest，文档示例能按公开接口编译和运行，性能结论可从基准配置与结果复核。

## 后续增强

- **并发读写**。已实现实例级读写锁，并验证查询和批量写入、删除及同名重建交错执行。后续根据实际负载中的锁等待和 P95 评估是否按因子细分锁。
- **磁盘持久化**。有重启后保留数据的需求时，先实现带格式版本和完整性校验的快照，验证保存、重载和损坏文件处理。明确写入何时算持久化成功。有逐批崩溃恢复要求时，再加入 WAL 和检查点。块缓存、压缩与 mmap 根据磁盘负载实测决定。
